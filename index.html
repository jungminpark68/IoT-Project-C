My Contribution

One-line summary: I built the weather data pipeline (API integration → parsing/processing → outputs) and delivered debug-friendly visualizations via Serial Monitor and OLED graphs.

KMA API Parsing & Processing Serial Output OLED Graph

(1) KMA API Integration & Data Processing

I implemented the request/response flow and extracted essential parameters (e.g., temperature, humidity, rainfall, wind direction/speed) into consistent numeric values used across modules.

Figure 1. Example of the API response parsing result (extracted fields mapped into weather parameters).

Implementation notes (click)
  • Handled base time/date logic for stable request timing (avoids missing recent data).
  • Parsed response fields and normalized units/format for downstream display.
  • Validated “value update” by comparing consecutive pulls and checking for missing fields.

(2) Real-time Serial Monitor Output (Wokwi)

To support quick debugging, I printed structured logs with clear labels and units. This made it easy to verify whether parsing and updates were working correctly in real time.

Figure 2. Serial Monitor output showing real-time updates of processed weather values for debugging.

What this helped me verify (click)
  • API call success/failure and response validity.
  • Parsed values are refreshed on schedule (no stale data).
  • Edge cases (missing fields / unexpected response) are visible immediately.

(3) OLED Graph Visualization

I implemented an OLED-based graph visualization so that trends can be understood at a glance. Instead of relying only on raw numbers, the graph provides an intuitive view of changes over time.

Figure 3. OLED screen visualizing weather changes as a graph for quick interpretation.

Graph design choices (click)
  • Used a compact layout to preserve readability on a 128×64 display.
  • Refreshed only necessary screen regions to reduce flicker.
  • Mapped numeric ranges to pixel ranges for stable visualization.

Method (My Implementation)

Pipeline Overview

  1. Request: Call KMA API with correct base_date/base_time and grid parameters.
  2. Parse: Extract required categories and convert into numeric values.
  3. Process: Normalize/format units and store latest values.
  4. Output: Print logs to Serial Monitor and render values/graphs on OLED.
